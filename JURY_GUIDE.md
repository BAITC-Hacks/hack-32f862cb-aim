# OptiStock: демонстрация и сдача

## Перед показом

Из корня установленного проекта на Windows:

```powershell
.\.venv\Scripts\python.exe scripts/local_dev.py
.\.venv\Scripts\python.exe scripts/jury_demo.py --fresh
```

Вторая команда импортирует материалы кейса, если они ещё не импортированы, и создаёт свежий расчёт с черновиками. Заказы она не утверждает. Без `--fresh` повторяется прежний идемпотентный запуск; для показа после пробных утверждений нужен свежий расчёт, учитывающий текущие обязательства.

Открыть **http://127.0.0.1:5173/agent**. Должны отображаться подключённый сервер, 3 909 SKU и последний завершённый запуск. Если выбран синтетический Demo workspace — нажать «Подключить локальный сервер».

При ошибке смотреть `var/local/api.log` и `var/local/worker.log`. Интерфейс показывает причину ошибки задачи и кнопку повтора. Ключи и `.env` на демонстрации не показывать.

| 2:35–3:00 | Качество данных и история | «Результат сохранён в PostgreSQL. Допущения об остатках, сроках и потерянном спросе видны. Отправка поставщику остаётся вне MVP». |

Количество 491 предполагает исходные параметры и отсутствие активных утверждённых заказов. Если перед показом уже утверждали заказы, новые количества могут уменьшиться: это учёт обязательств. Для повторной демонстрации отмените только свои тестовые заказы и выполните новый расчёт; не удаляйте базу и историю.

Для правки тестовой строки используйте количество `0` и причину «Исключено менеджером для демонстрации»; остальные строки оставьте положительными, иначе пустой заказ нельзя утвердить. После репетиции отмените тестовое обязательство. Сам агент утверждения не выполняет.

## Ответы на вероятные вопросы

- **Где используется AI-агент?** Разработка и проверка выполнены через Codex. В продукте работает серверный агент с фиксированным набором расчётных инструментов и журналом. Это детерминированный workflow, а не LLM-чат; числа не генерируются языковой моделью.
- **Почему 231 документ и 241 поправка?** Один документ может содержать несколько товаров. Корректируется 231 уникальный документ и 241 пара «товар–документ» у 190 SKU. Повторяющийся опт сохраняется.
- **Как проверить stockout?** На исходных файлах поправок stockout не получилось. Есть контролируемый тест: несколько месяцев нулевых запасов и заниженных продаж повышают прогноз и заказ после включения оценки. Нельзя заявлять наблюдавшийся эффект там, где его нет.
- **Какая точность?** Историческая проверка июня–августа 2026, только предшествующие данные; 3 240 сопоставимых наблюдений. По IEK в штуках WAPE 29,42% против 31,94% у среднего за 12 месяцев; по Systeme 21,14% против 27,52%. Это ошибка прогноза наблюдаемых продаж, не «процент уверенности» и не гарантия будущего результата. Полная методика — `CASE_EVIDENCE.md`.
- **Это реальные данные компании?** Это исходные файлы задания. Актуальность рабочих остатков не подтверждена. Синтетический каталог из Demo workspace используется отдельно.
- **Есть 1С, клиентские ID и отдельные склады?** CSV реализован, конкретный формат загрузки 1С не согласован. Клиентских ID и полного складского разреза в материалах нет; их наличие не имитируется.

## Готовый текст для платформы

**Название:** OptiStock — агент пополнения склада

**Описание:**

OptiStock решает кейс «Электрокомплект»: автоматически рассчитывает заказы поставщикам по истории продаж, остаткам и товарам в пути. Серверный агент проверяет Excel, корректирует разовые всплески при согласованных данных, учитывает сезонность, рост, сроки и ограничения заказа, затем готовит черновики по поставщикам. Менеджер видит числовое обоснование и риски, изменяет количество с причиной, утверждает заказ и выгружает CSV. Расчёты, версии и журнал действий сохраняются в PostgreSQL.

Реализованы React-интерфейс, FastAPI, отдельный worker, импорт 12 файлов IEK/Systeme Electric и полный сценарий на 3 909 товарах. На исходном сценарии подготовлена 491 позиция в двух заказах. Есть автоматические тесты обязательных факторов и историческая проверка прогноза. Ограничения источников и допущения показаны в интерфейсе. Разработка выполнена с AI-агентом Codex; внешние платные API для запуска не нужны.
