# OptiStock: реализуемый объём MVP

Пользователь уточнил: файлы тестовые, новых данных не будет; нужен работающий MVP с надёжным серверным фундаментом. Это заменяет прежний план ожидать дополнительные поля и инфраструктурные доступы. Название — **OptiStock**, Python-пакет и команда — `optistock`, префикс настроек — `OPTISTOCK_`.

| Область | Решение MVP и граница |
| --- | --- |
| Основа | FastAPI, Python 3.13, SQLAlchemy 2, psycopg 3, Alembic, PostgreSQL 17 |
| Очередь | Jobs в PostgreSQL и отдельный worker. Создание ресурса и задания атомарно; RabbitMQ/Celery и outbox пока не нужны |
| Выполнение | Lease 60 с, продление, до 3 попыток, процесс на задачу, таймаут 900 с. Запоздавший процесс не публикует результат с прежним token |
| Файлы | SHA-256 и общий приватный Docker volume; для нескольких узлов потребуется объектное хранилище |
| Доступ | Индивидуальные API-ключи, хеши в БД, серверные роли, отзыв. OIDC и браузерный login ещё не реализованы |
| Данные | Версии datasets и SKU snapshots; ключи/остатки/MOQ типизированы, неизменяемые ряды и происхождение — JSONB |
| Расчёт | Детерминированная модель со сценариями и числовым объяснением; прогнозная точность не заявляется |
| Заказы | Правки с причиной, ревизии, утверждение/отмена, обязательства, CSV, аудит. Отправки поставщикам и интеграции 1С нет |
| Конкуренция | Idempotency-Key, транзакционные блокировки, ревизия обязательств поставщику. Устаревший план блокируется консервативно даже для непересекающихся SKU |
| Интерфейс | Swagger и HTTP demo. React ещё не реализован, контракт `/api/v1` готов для подключения |

## Данные и допущения

Срез — 22 сентября 2026 года. В комплекте 3909 пар поставщик/код: IEK 3185, Systeme Electric 724. Месячные продажи есть у 3017 SKU. Динамика содержит 248884 операции с количеством; 31 строка без количества сохраняется в предупреждениях с координатами.

Каждый план сохраняет сроки, страховые дни, рост, включение сезонности/тренда/очистки/оценки stockout, правила пропусков, минимум и кратность по умолчанию, длину кабельной бухты. Объяснение содержит источники, исправления и предупреждения. Категории берутся из файла без выдуманной расшифровки; фильтр и явный словарь страховых дней по коду категории доступны в сценарии.

Без клиентского ID анализируются документы. Нулевой месячный снимок не считается доказанным интервалом дефицита. Брендовая сезонность — обозначенное приближение. Эти ограничения не блокируют тестовый сценарий.

## Границы готовности

Надёжность проверяется для одного узла и имеющегося объёма. PostgreSQL и файловый volume — единичные точки отказа; Docker restart не создаёт высокодоступность. Нет финансовых обещаний, доказанной точности прогноза, полной интеграции 1С, отправки заказов, приёмки поставок или React UI.

Следующие прикладные шаги: React, графики спроса/поправок, сравнение сценариев, проверка качества прогноза на временных срезах. OIDC и объектное хранилище нужны при расширении сценария эксплуатации; для текущего запуска дополнительные сервисы не требуются.
