# OptiStock: проверка backend MVP

Проверено локально 23 сентября 2026 года, Docker Desktop ARM64, Python 3.13, PostgreSQL 17.11. Это результаты конкретного запуска, не обещание SLA или точности прогнозирования.

## Автоматические проверки

- `python scripts/test.py -q`: **21 passed**, 14,32 с последнего полного запуска. Есть одно предупреждение библиотеки Starlette об устаревающем адаптере httpx TestClient; ошибок нет.
- `alembic check`: расхождений между моделями и миграцией нет.
- Ruff lint и format check: пройдены.
- Проверены разные роли, конкурентная идемпотентность, конфликт тела запроса, ревизии, одновременное утверждение двух планов, повторная закупка, возврат просроченной задачи в обработку и запрет записи по устаревшему token.
- Проверены поступление позже дефицита, MOQ/кратность/метры-бухты, редкий спрос, неполный месяц, очистка аномальных документов, сценарная оценка stockout, политика категорий, ограничения запросов, некорректный XLSX, отсутствие частичного результата и CSV-инъекции.

## Перезапуск и восстановление

1. Проверена инициализация образа PostgreSQL с пустым volume: созданы `optistock` и `optistock_test`, роль приложения `rolsuper = false`.
2. Перезапущены PostgreSQL, API и worker. Readiness восстановилась; сводки набора и плана совпали, оба утверждённых CSV совпали побайтно с результатами до перезапуска.
3. Выполнен `pg_dump -Fc`, создан архив исходных файлов из volume. Dump восстановлен через `pg_restore --exit-on-error` в отдельную временную БД: 3909 товаров, 3909 рекомендаций, 2 заказа. Временная проверочная БД после проверки удалена.

API остаётся запущенным на `http://localhost:8000`; доступ к данным требует персонального ключа. React, отправка поставщикам, интеграция 1С и HA-кластер не входят в проверенную реализацию.
