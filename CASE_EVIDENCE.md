# OptiStock — проверка требований кейса

Один кейс: автоматическое пополнение склада для «Электрокомплект». Проверено 23 сентября 2026 года. Числа ниже относятся к материалам задания и заданному сценарию, а не к фактическим закупкам компании.

| Требование | Реализация | Проверка |
| --- | --- | --- |
| Продажи, остатки, товары в пути, категории, рост влияют на заказ | Дневная проекция, политика категорий, сценарий роста | `tests/test_case_criteria.py::test_sales_stock_incoming_category_and_growth_each_change_order` |
| Сезонность и устойчивый рост | Нормированный сезонный профиль, согласованные отношения за 3 и 6 месяцев | `test_seasonality_and_sustained_growth_change_forecast` |
| Учёт потерянного спроса | Переключаемая оценка по нулевым снимкам запасов | `test_stockout_correction_increases_demand_and_order` |
| Разовая крупная продажа не раздувает регулярный заказ | Документный log-MAD с проверкой месячных итогов; повторяющийся опт сохраняется | В тесте всплеск +5000: отклонение очищенного заказа <10%, без очистки заказ >2× |
| Объяснение каждой позиции и заказы по поставщикам | Сохранённые исходные величины, поправки, MOQ, проекция; черновики IEK/Systeme | `tests/test_agent.py` и полный браузерный сценарий `frontend/e2e/agent-live.spec.ts` |

Общий сценарий проверен через реальные FastAPI, worker и PostgreSQL: импорт → агент → отчёт → карточка SKU → изменение с причиной → утверждение → скачивание CSV. Тестовое обязательство после проверки отменено; поставщикам ничего не отправлялось.

## Исходный прогон

12 XLSX, срез 2026-09-22, поставка 30 дней, цикл 30 дней, буфер 14 дней, рост 0%, остальные настройки по умолчанию:

- 3 909 товаров: IEK 3 185, Systeme Electric 724.
- 491 строка к заказу: 335 / 156 по поставщикам.
- 162 товара с риском дефицита до прихода новой поставки.
- 241 поправка по парам «товар–документ» в 231 уникальном документе у 190 SKU; 57 SKU с несовпадающими месячными итогами получают предупреждение, их несогласованные всплески не вычитаются. В агенте v2 счётчик документов учитывает документ один раз внутри поставщика и даты; сохранённые отчёты v1 содержат прежний счётчик поправок.
- Текущий остаток непосредственно из файла есть у 497 SKU; у остальных используется явно помеченное допущение.
- У 3 007 SKU есть хотя бы один завершённый месяц с числовым наблюдением; полностью пустая история не считается нулевым спросом.
- В этом наборе поправок stockout не получилось: это не скрывается и не подменяется искусственными аномалиями. Увеличение спроса при stockout доказано отдельным контролируемым тестом.

## Проверка прогноза на истории

Команда: `python scripts/backtest.py`, после импорта. Отчёт: `var/backtest.json`. Три последовательных прогноза июня, июля и августа 2026 года; на каждом шаге доступны только более ранние месяцы, документы, снимки и завершённые годовые сезонные профили. Будущие данные исключаются; это отдельно проверяется `tests/test_backtest.py`.

В сравнении участвуют одинаковые наблюдения для всех трёх моделей: нужны 12 предыдущих месяцев и прошлогоднее значение. Цель — наблюдавшиеся продажи, а не неизвестный истинный спрос. Пропущено 5 811 наблюдений, допущено 3 240. Единицы измерения разделены.

| Группа | Наблюдений SKU×месяц | WAPE OptiStock | Среднее 12 месяцев | Продажи того же месяца год назад |
| --- | ---: | ---: | ---: | ---: |
| IEK, м | 174 | 49,32% | 51,10% | 78,11% |
| IEK, упак | 105 | 34,30% | 37,79% | 37,64% |
| IEK, шт | 2 121 | 29,42% | 31,94% | 40,81% |
| Systeme, шт | 840 | 21,14% | 27,52% | 29,64% |

WAPE = сумма абсолютных ошибок / сумма наблюдаемых продаж; меньше — лучше. При нулевом знаменателе возвращается `null`. В JSON также есть MAE и смещение. Это один исторический эксперимент без подбора параметров по этим трём месяцам, не гарантия будущей точности и не доказательство финансовой экономии.

## Ограничения, которые нельзя закрыть выдуманными данными

Нет клиентских ID и согласованного складского разреза. Stockout — оценка по месячным снимкам, сезонность поставщика — неподтверждённый количественный proxy. Сроки, часть текущих запасов, MOQ и коэффициенты единиц требуют проверки менеджером. CSV работает, совместимость с конкретной обработкой 1С не заявляется. Произвольные форматы Excel, отправка заказов поставщикам, полноценная ERP-интеграция и публичный deployment не реализованы.

Финальная отправка через «Сдать решение» на платформе хакатона — отдельное действие команды; push в GitHub не заменяет её.
