# OptiStock — React frontend

React 19 + TypeScript (strict), Vite, React Router, Recharts и Lucide. Интерфейс доступен на **English / Русский / Қазақша**. Шрифт Inter и графические ресурсы поставляются локально; внешние сервисы для деморежима не нужны.

**Procurement agent** (`/agent`) также переведён на три языка: единый серверный запуск проверки, очистки, расчёта и подготовки черновиков, история, риски, сравнение очистки, JSON-отчёт, переход к согласованию заказа. Запуск требует API; агент не симулируется на демоданных. Локальный полный запуск без Docker — `python scripts/local_dev.py` из корня с установленными зависимостями и PostgreSQL; детали в корневом README.

## Язык интерфейса

Переключатель есть в верхней панели на каждой странице и в **Settings → Language**. При первом открытии выбирается язык браузера (`en`, `ru`, `kk`), для остальных — английский. Выбор хранится в `localStorage` под ключом `optistock.language`, сохраняется после перезагрузки и синхронизируется между вкладками. Переключение не перезагружает страницу, не меняет расчёты и сохраняет введённые параметры формы.

Переведены навигация, формы, статусы, графики, уведомления, известные ошибки сервера и пояснения расчёта. Даты и числа форматируются по языку; названия месяцев на казахском доступны и в браузерах с неполными данными ICU. Названия товаров, SKU, поставщики, содержимое исходных файлов и оригинальный JSON-отчёт агента сохраняются без перевода. Неизвестные серверные сообщения показываются в исходном виде для диагностики.

Словари находятся в `src/i18n/`: `messages.ts` — интерфейс, `extra.ts` — параметры и расчёт, `errors.ts` — известные ошибки. В каждой записи три значения: английский, русский, казахский. Браузерные проверки: `npm.cmd test -- e2e/i18n.spec.ts`.

Дополнительная проверка настоящего сервера после импорта: в PowerShell `$env:OPTISTOCK_LIVE_E2E='1'; npm.cmd exec playwright -- test e2e/agent-live.spec.ts --workers=1`. Она создаёт тестовые заказы, правит и утверждает один, скачивает CSV, затем отменяет тестовое обязательство. Обычный `npm test` этот тест пропускает.

## Быстрый запуск

Нужен Node.js 24. Из корня репозитория:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Открыть **http://localhost:5173**. В macOS/Linux используйте `npm` вместо `npm.cmd`. Суффикс `.cmd` позволяет запускать npm в Windows PowerShell без изменения Execution Policy.

По умолчанию включён явно обозначенный **Demo workspace**: 1 284 товара, интерактивные сценарии, заказы и отчёты. Демоданные сохраняются в localStorage. Их можно восстановить через Settings → Reset demo.

## Подключение API

1. Запустите API и worker по инструкции в корневом README.
2. Создайте персональный API-ключ: `docker compose exec api optistock create-key --name frontend-user --role admin`.
3. Откройте **Settings**, оставьте API address `/api/v1` и введите ключ.
4. Нажмите **Connect workspace**. Загрузите XLSX через **Add New → Import inventory** или выберите **Load samples**.
5. В **Forecast** задайте параметры и запустите расчёт. В **Orders** создайте черновики из прогноза, проверьте строки и утвердите заказ. CSV заказа доступен после утверждения.

Vite проксирует `/api` на `http://127.0.0.1:8000`. Для другого локального адреса скопируйте `.env.example` в `.env.local` и измените `API_PROXY_TARGET`. Можно также указать полный адрес сервера `/api/v1` в Settings; в этом случае сервер должен разрешать origin фронтенда через CORS.

Ключ хранится только в sessionStorage текущей вкладки; он не включается в сборку и не записывается в localStorage. Роли `viewer`, `planner`, `approver`, `admin` приходят с сервера. При ошибке подключения приложение показывает ошибку и не подменяет реальные данные демонстрационными.

## Разделы

| Страница  | Возможности                                                                                          |
| --------- | ---------------------------------------------------------------------------------------------------- |
| Dashboard | KPI, здоровье запасов, спрос выбранного SKU, распределение товаров, рекомендации и события           |
| Inventory | Поиск, статусы, поставщики, сортировка, пагинация, выбор строк, CSV, карточка с объяснением          |
| Suppliers | Товары, критические позиции и заказы каждого поставщика                                              |
| Orders    | Создание черновиков по поставщикам, редактирование с причиной, ревизии, утверждение, отмена, экспорт |
| Forecast  | Срок поставки, период обзора, страховое покрытие, рост, фильтры и переключатели модели               |
| Analytics | Покрытие, категории, качество данных, предупреждения и экспорт сводки                                |
| Reports   | CSV остатков, рекомендаций и событий; история и выбор наборов данных                                 |
| Settings  | Подключение, роль, активные набор и прогноз, восстановление демо                                     |

Глобальный поиск открывается по `Ctrl+K` / `Cmd+K`. `Enter` открывает первый результат, `Escape` закрывает модальные окна. Есть мобильная навигация и горизонтальная прокрутка широких таблиц.

## Семантика данных

- Реальные данные загружаются постранично, без ограничения первыми 50/200 записями. Каталог объединяется с рекомендациями по `item_id`.
- Неизвестный остаток отображается как `—`. Отсутствующий прогноз отображается как **No forecast**, а не Healthy.
- В реальном режиме бэкенд не предоставляет складскую детализацию: интерфейс показывает агрегат поставщика. Склады показаны только в демо.
- График показывает конкретный SKU. Историческая часть — очищенные месячные продажи, будущая — месячные суммы дневного прогноза; крайние месяцы могут быть неполными.
- Нет выдуманного процента уверенности модели, точности или динамики относительно прошлого месяца. Data Warnings — число товаров с предупреждениями, не число подтверждённых аномалий.
- Изменяющие запросы содержат `Idempotency-Key`. После сетевой ошибки/5xx повтор с тем же телом сохраняет ключ. Заказы изменяются с текущей ревизией; ошибки прав, MOQ и устаревшего плана отображаются пользователю.
- Задачи импорта и расчёта опрашиваются до завершения; неудачную задачу можно повторить. Worker должен быть запущен. При закрытии вкладки сервер продолжает задачу; после её завершения обновите страницу и выберите готовый набор/план в Settings.
- Деморасчёт иллюстрирует влияние сроков, покрытия и роста. Расширенные переключатели модели применяются настоящим бэкендом. Деморежим не воспроизводит статистическую модель Python.
- Создание черновиков из плана охватывает все рекомендованные позиции по поставщикам, согласно API. Экспорт отфильтрованной таблицы отделён от экспорта утверждённого заказа.

## Сборка и Docker

```powershell
npm.cmd run build
npm.cmd run preview
```

Результат — `dist/`. Preview служит для проверки статической сборки; для API используйте полный адрес сервера в Settings с разрешённым CORS или запускайте через Compose.

Корневой `docker compose up -d --build` также запускает frontend на **http://localhost:5173**. Nginx отдаёт SPA, поддерживает прямые ссылки на страницы и проксирует `/api/` в сервис `api:8000`. Не запускайте одновременно Vite и Compose frontend на одном порту.

## Проверки

```powershell
npm.cmd run lint
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd test
npm.cmd run format:check
```

Playwright проверяет поиск и клавиатуру, фильтры и CSV, изменение/утверждение/отмену заказов, сохранение демо, сценарии, все страницы и мобильную вёрстку. Тесты API используют ответы по контракту FastAPI и проверяют Bearer, идемпотентность, ревизии, права, неизвестный запас и polling. Это не замена интеграционным тестам настоящего PostgreSQL/worker.

